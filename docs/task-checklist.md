## 阶段 3：专注任务清单模块（非 AI）

### 3.1 交互语义重构（先消除用户认知混淆）
- [x] 统一术语：将“完成”拆分为“完成任务”和“完成番茄（系统事件）”
- [x] 列表文案重构：使用“番茄投入 N 次 / 专注时长 M 分钟”，避免歧义表达
- [x] 明确交互规则：番茄归零只累计投入，不自动将任务标记为完成

### 3.2 数据模型重构
- [x] `TaskRecord` 字段从 `completed: bool` 演进为 `status: todo|done`
- [x] 任务专注时长字段从 `focus_minutes` 演进为 `focus_seconds`（展示层再换算分钟）
- [x] 保留并规范“当前专注任务 id”状态字段（`session_state.current_task_id`）

### 3.3 持久化与兼容迁移
- [x] 任务 JSON 存储继续使用 `data/tasks/`
- [x] 增加旧数据兼容：读取时自动兼容 `completed/focus_minutes` 老字段
- [x] 写入统一新结构，保证后续数据口径一致

### 3.4 任务服务重构
- [x] 保留任务基础能力：新增、完成/恢复、删除
- [x] 番茄累加逻辑改为累计 `focus_seconds`，展示层负责分钟换算
- [x] 删除当前任务时自动清空当前任务选择，避免悬空引用

### 3.5 UI 与流程重构
- [x] 页面增加“当前专注任务”主入口，任务选择前置
- [x] 未选择任务时给出清晰提示，但不阻塞计时
- [x] 任务列表分组展示：待办任务、已完成任务
- [x] 删除操作增加二次确认（防误删）
- [x] 番茄完成后给出明确反馈（例如“已为任务 X 累计 1 个番茄”）

### 3.6 与计时器联动重构
- [x] 继续复用归零单次触发机制，确保任务累加不重复
- [x] 仅在“运行 -> 归零”事件中写入任务投入数据
- [x] 未选择任务时仅写全局统计，不写任务统计

### 3.7 自测（按新交互验收）
- [x] 新增任务后立即可见，可设为当前专注任务
- [x] 完成一次番茄后，当前任务“番茄投入 +1”，专注时长按秒累计
- [x] 手动“完成任务”不影响历史番茄投入数据
- [x] 删除任务后不会触发 `session_state` 键冲突，且当前选择自动纠正
- [x] 刷新页面后任务状态与投入数据不丢失

验收点：
- [x] 用户能清晰区分“任务完成”与“番茄完成”，任务联动稳定可用
